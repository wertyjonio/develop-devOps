# Обучение DevOps — Справочник инженера

Мой личный интерактивный справочник по системе контроля версий Git, администрированию Linux, сетевой безопасности и автоматизации задач. 
*Разработка ведется на ПК со второй ОС. Стек: VS Code + WSL (Ubuntu) + Bash + Git.*

---

## 📦 СТУПЕНЬ 1: Система контроля версий Git

Git устроен как трехступенчатая система: **Рабочая директория** (файлы на диске) ➡️ **Индекс / Staging Area** (зона подготовки файлов к отправке) ➡️ **Локальный коммит** (сохраненный слепок кода) ➡️ **Удаленный репозиторий** (GitHub / GitLab).

### Базовый рабочий цикл:
*   `git status` — **Самая важная команда контроля**. Показывает состояние твоего репозитория прямо сейчас. 
    *   *Красные файлы (Untracked / Modified):* Изменения есть только у тебя на ПК.
    *   *Зеленые файлы (Staged):* Файлы добавлены в индекс и готовы зафиксироваться в коммит.
*   `git add .` — добавить **вообще все** новые, измененные и удаленные файлы в текущей папке в индекс (подготовить к отправке).
*   `git add <имя_файла>` — **Точечное добавление**. Подготавливает к отправке строго один конкретный файл. Помогает, когда в папке много мусора, а отправить на GitHub нужно только один конспект.
*   `git reset` — **Отмена подготовки**. Очищает текущий индекс. Все файлы из «зеленой» зоны подготовки возвращаются в «красную» рабочую зону. Сами файлы на диске при этом не изменяются и код не теряется. Полезно, если случайно сделал `git add .` вместо точечного добавления.
*   `git commit -m "тип: описание изменений"` — зафиксировать все «зеленые» файлы из индекса в локальный коммит (сделать снимок кода в истории).
    *   *DevOps-стандарт (Conventional Commits):* Использовать префиксы в сообщениях: `docs:` (для конспектов/документации), `feat:` (новый скрипт/фича), `fix:` (исправление багов), `chore:` (наведение порядка в папках).
*   `git push` — отправить все свои локальные коммиты на удаленный сервер (например, в ветку `main` на GitHub).

## 🐧 СТУПЕНЬ 2: Linux Basics & Автоматизация

### 1. Продвинутая навигация и аудит файлов
*   `pwd` (Print Working Directory) — показать текущий абсолютный путь от корня системы (`/`).
*   `file <имя>` — определить реальный тип файла по его сигнатуре (магическим байтам), а не по расширению (покажет: текст, бинарник, скрипт, архив).
*   `stat <имя>` — показать полную метаинформацию о файле: размер, владельца, права доступа в числовом виде и три главные даты (время создания, изменения контента, последнего доступа).
*   `tree` — показать структуру текущей папки и всех вложений в виде наглядного графического дерева.
*   `find <где> -name "<маска>"` — мощный поиск файлов на диске. 
    *   *Пример:* `find . -name "*.md"` — искать все Markdown-файлы в текущей папке и подпапках.
    *   *⚠️ Подводный камень:* Обязательно писать флаг `-name`. Если написать просто `find . "*.sh"`, утилита решит, что папка для поиска называется `*.sh` и выдаст ошибку.
*   `locate <имя>` — мгновенный поиск файлов по всей системе через готовую базу данных. Работает быстрее `find`, но требует обновления базы командой `updatedb` после создания новых файлов.
*   `ln <файл> <имя_ссылки>` — создание **жесткой ссылки** (hard link). Ведет на те же данные на диске. Если удалить оригинал, жесткая ссылка продолжит работать.
*   `ln -s <файл> <имя_ссылки>` — создание **символической ссылки** (soft/symbolic link). Аналог ярлыка в Windows. Если удалить оригинал, ссылка станет «битой» (нечитаемой).

### 2. Потоки данных и перенаправления
В Linux у любого процесса есть три стандартных потока ввода/вывода:
*   `0` (`stdin`) — стандартный ввод (клавиатура / входящий поток из пайпа).
*   `1` (`stdout`) — стандартный полезный вывод (экран).
*   `2` (`stderr`) — стандартный вывод ошибок (экран).

*   `>` — направить `stdout` в файл с **полной перезаписью** старого содержимого.
*   `>>` — направить `stdout` в файл, **дописывая** строки в самый конец (сохраняет старые данные).
*   `2>` — перенаправить исключительно поток ошибок `stderr` в файл, скрыв их из терминала.
    *   *Пример:* `cat non_existent.txt 2> errors.log`
*   `2>&1` — склеить поток ошибок (`2`) с полезным выводом (`1`). 
    *   *Пример:* `ping -c 1 8.8.8.8 > /dev/null 2>&1` — отправляет и полезный вывод, и возможные ошибки сети в «черную дыру» Linux (`/dev/null`), обеспечивая идеальную чистоту экрана.
*   `|` (Пайп / Конвейер) — передает `stdout` первой команды на `stdin` второй команды, позволяя строить цепочки обработки.

### 3. Переменные окружения
*   `env` — вывести список всех активных глобальных (системных) переменных текущей сессии.
*   `export VAR="value"` — превратить локальную переменную терминала в глобальную переменную окружения, доступную для всех дочерних процессов и скриптов.
    *   *⚠️ Подводный камень:* Вокруг знака `=` **нельзя ставить пробелы** (`VAR = "val"` вызовет ошибку). Значок `$` ставится только при чтении переменной (`echo $VAR`), при создании он не нужен. Имена переменных чувствительны к регистру (`$BACKUP_DIR` и `$BACHUP_DIR` — разные вещи).
*   `$PATH` — критически важная переменная. Содержит список папок, разделенных двоеточием, в которых Linux ищет исполняемые файлы команд.
    *   *Временное добавление пути (до закрытия терминала):* `export PATH="$PATH:/home/user/my_folder"` (обязательно сохранять старый `$PATH` через двоеточие!).
    *   *Добавление текущей папки (`.`):* `export PATH="$PATH:."` — позволяет запускать скрипты из текущей папки просто по имени: `script.sh`.
    *   *⚠️ Безопасность:* На реальных серверах хранить точку `.` в `$PATH` опасно, так как злоумышленник может подкинуть вредоносный исполняемый файл в рабочую папку.
*   `.bashrc` — скрытый конфигурационный файл в домашней директории пользователя. Выполняется **каждый раз при открытии нового окна терминала**. Именно сюда нужно прописывать кастомные `export PATH` и алиасы для постоянной работы.
*   `.bash_profile` / `.profile` — выполняются **один раз** при первом входе (логине) пользователя в систему.

### 4. Комплексная работа с текстом (Текстовые пайплайны)
*   `grep [опции] "шаблон" <файл>` — поиск строк по тексту или регулярному выражению.
    *   `-i` — игнорировать регистр букв.
    *   `-v` — инвертировать поиск строк внутри файла (показать строки, где текста **нет**). Например: убрать успешные логи `grep -v "200 OK"`.
    *   `-n` — вывести номера строк.
    *   `-E` — включить расширенные регулярные выражения. Символ `|` внутри шаблона означает логическое «ИЛИ» (`grep -E '404|500'`).
    *   `-L` (или `--files-without-match`) — выводит исключительно **имена файлов**, внутри которых заданный текст ни разу не встретился. Применяется для поиска файлов-исключений.
*   `sort` — сортировка строк по алфавиту. Флаг `-n` включает правильную сортировку чисел, флаг `-r` разворачивает сортировку в обратном порядке.
*   `uniq` — удаление **повторяющихся подряд** строк. Перед `uniq` всегда должна идти команда `sort`.
    *   `-c` — посчитать количество уникальных повторений каждой строки.
*   `cut` — вертикальное вырезание колонок текста. Флаг `-d` задает символ-разделитель, флаг `-f` указывает номер нужного столбца.
    *   *Пример отсечения знака %:* `cut -d '%' -f 1` (делит строку `45%` на части и берет первую).
*   `wc` (Word Count) — подсчет метрик текста. Флаг `-l` считает точное количество строк.
*   `xargs` — берет строки из пайпа и передает их в качестве аргументов команде, которая не умеет читать `stdin` напрямую. Флаг `-r` отменяет запуск следующей команды, если на вход ничего не пришло.
    *   *Пример:* `find . -name "*.log" | xargs -r rm`
*   `sed` — потоковый текстовый редактор. Используется для автозамены «на лету».
    *   *Пример:* `sed -i 's/old/new/g' file.txt` (флаг `-i` сохраняет изменения в файл).
*   `awk` — мощный процессор структурированного текста. Автоматически разбивает строки на столбцы `$1`, `$2`, `$3` по пробелам.
    *   *Пример анализа реального лога (Топ-3 IP со статусом 200):*
        `grep "200" access.log | awk '{print $1}' | sort | uniq -c | sort -nr | head -n 3`

### 5. Сетевое администрирование и пакетный менеджер
Управление службами и программами на сервере (выполняется через `sudo` от имени суперпользователя):
*   `sudo apt update` — обновить локальную «витрину» доступного ПО из репозиториев в интернете. Выполняется перед установкой любого софта.
*   `sudo apt install -y <пакет>` — установить программу на диск. Флаг `-y` автоматически одобряет установку.
    *   *Пример:* `sudo apt install -y openssh-server` (установка SSH-сервера, чтобы к машине можно было подключиться удаленно).
*   `sudo service <служба> start` — запустить фоновый процесс (службу/демона) в памяти системы прямо сейчас.
    *   *Пример:* `sudo service ssh start` (начинает слушать порт 22).

### 6. Удаленное управление через SSH (Secure Shell)
SSH — фундаментальный инструмент DevOps-инженера для безопасного шифрованного управления удаленными серверами.

#### Генерация и настройка беспарольного входа (Best Practice)
1.  **Создание пары ключей на своем ПК:** `ssh-keygen -t rsa -b 4048`. 
    Генерирует секретный приватный ключ `id_rsa` (мой «паспорт», никому не показывать!) и публичный ключ `id_rsa.pub` (цифровой «замок»).
2.  **Привязка к серверу:** `ssh-copy-id user@remote_ip`.
    Дописывает мой публичный ключ на сервер в файл `~/.ssh/authorized_keys`. После этого вход по паролю больше не требуется, роботы могут авторизовать скрипты автоматически.
    *   *💡 Локальный тест (`петля`):* Можно привязать ключ самому себе внутри WSL через адрес `127.0.0.1` (`ssh-copy-id wert@127.0.0.1`).
3.  **Вход на сервер:** `ssh user@remote_ip` или выполнение удаленной команды в один пролет: `ssh user@remote_ip "uptime"`.

#### Передача файлов по сети
*   `scp <файл> user@remote_ip:<путь>` — Secure Copy. Перенос одиночного файла через SSH на удаленную машину.
*   `rsync -avz --progress <папка>/ user@remote_ip:<путь>` — умная синхронизация папок. Сравнивает файлы и передает только изменившиеся части (**дельту**), экономя время и трафик.

### Файл конфигурации `~/.ssh/config`
Позволяет создавать короткие алиасы для сложных подключений, чтобы не вводить порты и IP вручную:
```text
Host prod-server
    HostName 194.22.11.5
    User admin
    Port 2222
    IdentityFile ~/.ssh/my_key.pem
```
*Запуск одной командой:* `ssh prod-server`.

### SSH-туннелирование (Port Forwarding)
Проброс закрытого порта удаленного сервера (например, базы данных `3306`) на свой локальный ПК:
`ssh -f -N -L 8080:localhost:3306 user@remote_ip`
*   `-L 8080:localhost:3306` — связать мой локальный порт 8080 с удаленным портом 3306.
*   `-f` — отправить команду SSH работать тихо в фоновый режим сразу после подключения.
*   `-N` — не открывать удаленную командную строку (шелл), использовать сессию только для туннеля данных.

## 7. Автоматизация: Bash-скриптинг

Каждый скрипт — это текстовый файл с расширением `.sh`, написанный строго построчно. Запускается через `bash script.sh`.

### Системные коды возврата (Exit Codes)
Каждая команда после работы возвращает число операционной системе. Переменная **`$?`** хранит статус *последней* выполненной команды:
*   `0` — Успех. Команда выполнена идеально.
*   `1` (и от 1 до 255) — Ошибка. Код используется роботами (CI/CD) для аварийной остановки деплоя. 
*   Команда `exit 1` внутри скрипта немедленно прерывает его работу и возвращает системе статус аварии.

### Шаблон продвинутого скрипта (Переменные, Условия `if/else`, Циклы `for`)
```bash
#!/bin/bash    # Шебанг (Shebang) — указывает системе интерпретатор для выполнения

# 1. Проверка переменных окружения на пустоту (флаг -z)
if [ -z "$DB_PASSWORD" ]; then
    echo "[ERROR] Секретный пароль базы данных не задан в системе!"
    exit 1  # Аварийный останов
fi

# 2. Цикл for по строкам текстового файла
# Конструкция $(cat ...) считывает инвентарь серверов
for ip in $(cat servers.txt)
do
    echo "--- Сканирую сервер $ip ---"
    
    # Пингуем хост 1 пакетом. Склеиваем stdout и stderr (2>&1) 
    # и отправляем в «черную дыру» /dev/null, чтобы очистить экран.
    ping -c 1 $ip > /dev/null 2>&1
    
    # Проверяем код возврата утилиты ping
    # ⚠️ Важно: Внутри квадратных скобок пробелы ОБЯЗАТЕЛЬНЫ с обеих сторон!
    if [ $? -eq 0 ]; then
        echo "[OK] Сервер доступен. Отправляю конфигурацию..."
        scp nginx.conf wert@$ip:/tmp/
    else
        echo "[WARNING] Сервер $ip лежит или закрыт файрволом!"
    fi
done
```

### Важные операторы сравнения чисел в `if`:
*   `-eq` — равно (equal)
*   `-ne` — не равно (not equal)
*   `-gt` — больше (greater than)
*   `-lt` — меньше (less than)
*   `-ge` — больше или равно (greater or equal)

## 8. Права доступа (`chmod`)

*   У каждого объекта в Linux есть 3 категории доступа: **U**ser (Владелец), **G**roup (Группа владельца), **O**thers (Все остальные).
*   Базовые типы прав:
    *   `r` (read) — чтение содержимого.
    *   `w` (write) — изменение содержимого (удаление/запись).
    *   `x` (execute) — право на запуск файла как программы или скрипта.
*   `chmod +x script.sh` — добавить флаг исполняемости для владельца, после чего Bash позволит запускать скрипт напрямую через `./script.sh` (в терминале имя файла подсветится зеленым цветом).

### 9. Первичная настройка и защита сервера (Server Hardening)
Пошаговый алгоритм защиты нового сервера от сетевых атак сразу после развертывания («золотой чек-лист» DevOps):

1.  **Создание изолированного пользователя для повседневной работы:**
    `sudo adduser devops_jun` — создает нового изолированного юзера (работать под привилегированным `root` напрямую запрещено стандартами ИБ).
    `sudo usermod -aG sudo devops_jun` — добавляет пользователя в группу `sudo` для возможности контролируемого временного повышения прав. Каждое действие логируется в `/var/log/auth.log`.
2.  **Настройка беспарольного SSH-доступа по ключам:**
    `ssh-copy-id devops_jun@<IP_сервера>` — дописывает локальный публичный ключ ПК в файл `~/.ssh/authorized_keys` конкретного пользователя на сервере для входа без паролей.
3.  **Запечатывание конфигурации безопасности SSH-демона:**
    `sudo vim /etc/ssh/sshd_config` — внесение жестких запретов:
    *   `PasswordAuthentication no` — отключает вход по обычным паролям (защита от брутфорса ботами).
    *   `PermitRootLogin no` — запрещает сетевой вход под пользователем `root` напрямую.
    `sudo service ssh restart` — перезапуск службы в памяти для применения новых конфигураций.
4.  **Развертывание и активация межсетевого экрана (Файрвола):**
    `sudo apt update && sudo apt install -y ufw` — установка утилиты управления файрволом UFW.
    `sudo ufw allow 22/tcp` — **Критический шаг!** Добавление явного исключения для порта 22 (SSH). Если включить файрвол без этого правила, произойдет перманентная самоблокировка на сервере.
    `sudo ufw enable` — активация файрвола в боевой режим. Переводит закрытие всех остальных портов под «глухую стену».
    `sudo ufw status` — аудит активности сетевых правил.

### 10. Состояния процессов и сигналы управления (Траблшутинг)
Фундаментальные механизмы ядра Linux для контроля жизненного цикла программ и диагностики их поведения:

1. **Базовые состояния процессов (Колонка STAT в `ps aux`):**
   * `R` (Running / Runnable) — Процесс выполняется прямо сейчас или полностью готов к работе и ждет очереди к CPU.
   * `S` (Interruptible Sleep) — Управляемый сон. Процесс ожидает внешнего события (ввода пользователя, сетевого пакета или таймера). Это дефолтное состояние большинства программ.
   * `D` (Uninterruptible Sleep) — Глубокий сон. Процесс завис на операции ввода-вывода (I/O), ожидая ответа от жесткого диска или сетевой папки. Его невозможно прервать или убить через `kill -9`.
   * `T` (Stopped) — Процесс остановлен или поставлен на паузу пользователем (например, через `Ctrl + Z`).
   * `Z` (Zombie) — Процесс завершен, но его родитель еще не прочитал код возврата. Память освобождена, но запись в таблице PIDs сохраняется.
2. **Основные модификаторы состояний (Дополнительные символы в STAT):**
   * `<` — Процесс имеет высокий приоритет (забирает ресурсы у других).
   * `N` — Процесс имеет низкий приоритет (работает, только когда система свободна).
   * `s` — Лидер сессии (например, главный процесс вашей командной оболочки).
   * `l` — Многопоточный процесс (внутри него запущено несколько Thread'ов).
   * `+` — Процесс выполняется на переднем плане (foreground) в текущем терминале.
3. **Критические сигналы управления (Используются в `kill <SIGNAL> <PID>`):**
   * `SIGTERM (15)` — Вежливое завершение. Стандартный сигнал при вызове `kill`. Процесс плавно закрывает файлы, сохраняет сессии и завершает работу.
   * `SIGKILL (9)` — Принудительное уничтожение (`kill -9`). Сигнал обрабатывается самим ядром, которое мгновенно стирает процесс из RAM. Процесс не успевает сохранить данные (опасно для баз данных).
   * `SIGHUP (1)` — Перезапуск конфигурации. Заставляет системные демоны (например, Nginx) перечитать конфигурационные файлы на лету без полной остановки сервиса.
   * `SIGINT (2)` — Прерывание с клавиатуры. Посылается процессу на переднем плане при нажатии комбинации `Ctrl + C`.
   * `SIGSTOP (19)` — Мгновенная заморозка. Посылается при нажатии `Ctrl + Z`. Процесс полностью перестает использовать CPU, оставаясь в оперативной памяти.

### 11. Аудит, мониторинг и поиск аномалий
Практические команды для инспекции запущенных программ и выявления утечек ресурсов:

1. **Детальный снимок всех процессов в системе:**
   `ps aux` — выводит полный список процессов всех пользователей без привязки к терминалу.
   * **Критические метрики:** Колонка `RSS` показывает реальную физическую память (RAM) в килобайтах, занимаемую процессом прямо сейчас. Ориентироваться при авариях нужно строго на неё, а не на виртуальную память `VSZ`.
2. **Поиск конкретного процесса в выводе:**
   `ps aux | grep "[n]ginx"` — фильтрация списка процессов через конвейер. Обертывание первой буквы в квадратные скобки `[ ]` — регулярное выражение, которое заставляет утилиту `grep` проигнорировать саму себя в выводе.
3. **Выявление «прожорливых» процессов (Топ по памяти):**
   `ps aux --sort=-%mem | head -n 6` — сортирует процессы по убыванию потребления оперативной памяти и выводит топ-5 нарушителей с заголовком таблицы. Помогает быстро найти виновника утечки ресурсов.
4. **Анализ связей процессов (Поиск Сирот и Зомби):**
   `ps axjf` — строит иерархическое дерево процессов с отображением `PPID` (Parent Process ID — идентификатор родителя).
   * **Поиск зомби без ложных срабатываний:** `ps auwx | awk '$8 ~ /Z/'` — проверяет строго 8-ю колонку вывода (STAT) на наличие признака зомби.

### 12. Управление жизненным циклом служб (SystemD)
Архитектурный подход к превращению обычных скриптов в автоматизированные фоновые службы (демоны) с гарантией отказоустойчивости:

1. **Создание конфигурации системной службы (Юнита):**
   `sudo vim /etc/systemd/system/my-app.service` — создание файла конфигурации службы в защищенной директории.
   * **Базовый шаблон безопасного юнита:**
     ```ini
     [Unit]
     Description=My DevOps App
     After=network.target      # запуск строго после поднятия сети

     [Service]
     Type=simple
     ExecStart=/home/wert/app.sh  # абсолютный путь к исполняемому файлу
     Restart=always            # автореанимация: SystemD мгновенно перезапустит процесс при падении
     User=wert                 # запуск от имени изолированного юзера (ИБ-стандарт)

     [Install]
     WantedBy=multi-user.target # необходимо для корректного автозапуска при старте ОС
     ```
2. **Применение конфигурации и запуск службы:**
   `sudo systemctl daemon-reload` — заставляет SystemD перечитать файлы в папке `/etc/systemd/system/` и увидеть новый или измененный юнит.
   `sudo systemctl start my-app.service` — запускает службу (под капотом ядро делает системные вызовы `fork()` и `exec()`).
   `sudo systemctl enable my-app.service` — добавляет службу в автозапуск при включении сервера.
3. **Контроль состояния и чтение логов:**
   `sudo systemctl status my-app.service` — аудит текущего состояния службы (показывает статус `active (running)`, выделенный `PID` и потребление ресурсов).
   `journalctl -u my-app.service -f` — вызов централизованного сборщика логов. Флаг `-f` (follow) фиксирует терминал и выводит логи приложения в режиме реального времени.

 ### 14. Мониторинг ресурсов
 пример скрипта для мониторинга ресурсов:
 #!/bin/bash

# monitor.sh - простой мониторинг системы

LOG_FILE="/var/log/monitor.log"
THRESHOLD_CPU=80
THRESHOLD_MEMORY=80
THRESHOLD_DISK=90

log_message() {
    echo "$(date '+%Y-%m-%d %H:%M:%S') - $1" >> "$LOG_FILE"
}

check_cpu() {
    CPU_USAGE=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}' | awk -F'%' '{print $1}')
    if (( $(echo "$CPU_USAGE > $THRESHOLD_CPU" | bc -l) )); then
        log_message "WARNING: High CPU usage: ${CPU_USAGE}%"
        # Отправить алерт
        echo "High CPU usage: ${CPU_USAGE}%" | mail -s "CPU Alert" admin@company.com
    fi
}

check_memory() {
    MEMORY_USAGE=$(free | grep Mem | awk '{printf("%.1f", $3/$2 * 100.0)}')
    if (( $(echo "$MEMORY_USAGE > $THRESHOLD_MEMORY" | bc -l) )); then
        log_message "WARNING: High memory usage: ${MEMORY_USAGE}%"
    fi
}

check_disk() {
    df -h | grep -vE '^Filesystem|tmpfs|cdrom' | awk '{print $5 " " $1}' | while read output;
    do
        usage=$(echo $output | awk '{print $1}' | cut -d'%' -f1)
        partition=$(echo $output | awk '{print $2}')
        
        if [ $usage -ge $THRESHOLD_DISK ]; then
            log_message "WARNING: High disk usage on $partition: ${usage}%"
        fi
    done
}

# Основная логика
log_message "Starting system monitoring"
check_cpu
check_memory  
check_disk
log_message "Monitoring completed"

### #️⃣15. Важные практические знания

#### 🖥️ 1. Работа с процессами и памятью

* `ps aux | grep [m]alware`
  * **Для чего:** Найти запущенный процесс, не выводя в терминал сам `grep`. Квадратные скобки вокруг первой буквы ломают совпадение для самого `grep`.

* `lsof /var/log/app.log`
  * **Для чего:** Узнать, какой именно процесс (его имя и PID) прямо сейчас открыл и заблокировал этот файл.

* `lsof | grep deleted`
  * **Для чего:** Найти файлы, которые уже удалены через `rm`, но всё еще занимают место на диске, потому что их процессы не закрылись.

* `sudo cp /proc/PID/exe ~/recovered_file`
  * **Для чего:** Восстановить (скопировать) удаленный бинарник запущенного процесса прямо из оперативной памяти.

* `kill PID`
  * **Для чего:** Безопасная, мягкая остановка процесса (сигнал 15 / `SIGTERM`). Дает ему время сохранить данные. Стандарт в DevOps.

* `kill -9 PID`
  * **Для чего:** Жесткое уничтожение процесса на уровне ядра (сигнал 9 / `SIGKILL`). Применяется, только если он намертво завис.


#### 💽 2. Очистка диска и лимиты

* `sudo truncate -s 0 /var/log/app.log`
  * **Для чего:** Мгновенно обнулить (осушить) файл до 0 байт, не удаляя его и не ломая запущенную программу.

* `echo -n "" | sudo tee /var/log/app.log`
  * **Для чего:** Альтернативный способ обнуления файла через поток `tee`, обходящий ошибку прав доступа `Permission denied`.

* `ulimit -n`
  * **Для чего:** Показать максимальное количество файлов, которое текущий пользователь может открыть одновременно.


#### 📝 3. Работа с текстам и конфигами

* `grep -Ev "^#|^$" /etc/nginx/nginx.conf`
  * **Для чего:** Вывести конфиг в чистом виде, полностью вырезав из него пустые строки (`^$`) и комментарии (`^#`).

* `grep "404" access.log | awk '{print $1}' | sort | uniq -c | sort -nr`
  * **Для чего:** Классический конвейер DevOps. Отбирает ошибки 404, вырезает первый столбец (IP), считает уникальные адреса и сортирует их от самых частых к редким.


#### 🔍 4. Поиск, рекурсия и архивы

* `sudo find /etc/ -type f \( -name "*.key" -o -name "*.txt" \) -mtime -2`
  * **Для чего:** Найти в `/etc/` только файлы (`-type f`), измененные за последние 2 дня (`-mtime -2`), с расширением `.key` ИЛИ (`-o`) `.txt`.

* `Флаг рекурсии (-r или -R)`
  * **Для чего:** Автоматическое применение команды (например, `rm -rf`, `chmod -R`, `chown -R`) к целевой папке и всему её содержимому на любую глубину.

* `sudo tar -czvf ~/backup.tar.gz /etc/nginx/`
  * **Для чего:** Создать (`c`) сжатый через gzip (`z`) архив, выводя процесс на экран (`v`), в файл (`f`) по указанному пути.


#### 🌐 5. Сеть и файловая система

* `sudo tcpdump -i eth0 -n -c 10 ip`
  * **Для чего:** Перехватить на сетевой карте `eth0` ровно 10 пакетов (`-c 10`), показывая только чистые IP-адреса (`-n`), игнорируя системный шум (`ip`).

* `sudo mount /dev/loop0 /mnt/backup`
  * **Для чего:** Временно примонтировать (подключить) диск к созданной папке, чтобы прочитать его содержимое.

* `timeout 3 bash -c 'cat < /dev/null > /dev/tcp/://google.com' && echo "Open" || echo "Closed"`
  * **Для чего:** Проверить, открыт ли порт на удаленном сервере, силами одного только Bash (без использования `telnet` или `netcat`).

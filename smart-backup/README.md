# Smart Docker Backup Utility & Systemd Timer Automation

Автоматизированная отказоустойчивая система резервного копирования инфраструктуры. Проект представляет собой утилитарный контейнер на базе Alpine Linux, который упаковывает целевые директории в сжатые архивы и управляется системным таймером операционной системы по строгому календарному расписанию.

## 🏗️ Архитектура и Физика процессов

Система разделена на три уровня изоляции:
1. **Хост (Уровень ОС):** Инициализирует событие по будильнику Systemd, монтирует физические папки сервера внутрь виртуальной среды и запускает изолированный процесс.
2. **Контейнер (Уровень Docker):** Легковесная изолированная среда (Alpine Linux + Bash), которая не имеет прямого доступа к хосту, а видит только выделенные ей целевые папки.
3. **Скрипт (Уровень Автоматизации):** Проверяет целостность данных, пакует файлы с помощью `tar -czf` со сменой контекста путей (`-C`) и возвращает готовый архив на хост через смонтированный том.

## 🛠️ Компоненты проекта

### 1. Консольный скрипт резервного копирования (`backup.sh`)
Скрипт выполняет валидацию точек монтирования и архивацию данных.
* **Внутренний источник (In-Container Source):** `/data/src`
* **Внутреннее назначение (In-Container Destination):** `/data/backups`

### 2. Спецификация сборки образа (`Dockerfile`)
Сборка выполнена по стандартам минимизации размера образов (размер итогового слоя составляет менее 30 МБ) с использованием пакетного менеджера `apk` без сохранения локального кэша индексов.

## 🚀 Инструкция по развертыванию и запуску

### Шаг 1. Локальная сборка образа
Сборка кастомного образа из корня директории проекта:
```bash
docker build -t wertyjonio/backup-utility:latest .
```

### Шаг 2. Ручное тестирование монтирования (Volumes)
Проверка корректности проброса файловых потоков между хостом и изолированным контейнером:
```bash
docker run --rm \
  -v ~/projects/devops-learning:/data/src \
  -v ~/projects/backups:/data/backups \
  wertyjonio/backup-utility:latest
```

## ⏱️ Автоматизация через Systemd (Уровень Хоста)

Для работы в фоновом режиме 24/7 в операционную систему хоста интегрирована пара конфигурационных юнитов. Имена файлов до точки совпадают буква в букву для корректного связывания процессов.

### 1. Сервисный юнит (`/etc/systemd/system/docker-backup.service`)
Конфигурация однократного запуска (`Type=oneshot`) от имени локального пользователя для сохранения корректных прав доступа к создаваемым файлам архивов:
```ini
[Unit]
Description=Run Smart Backup Docker Container
After=docker.service
Requires=docker.service

[Service]
Type=oneshot
User=wert
ExecStart=/usr/bin/docker run --rm -v /home/wert/projects/devops-learning:/data/src -v /home/wert/projects/backups:/data/backups wertyjonio/backup-utility:latest
```

### 2. Юнит системного таймера (`/etc/systemd/system/docker-backup.timer`)
Будильник, настраивающий ежедневный триггер в 03:00 ночи. Параметр `Persistent=true` гарантирует запуск пропущенной задачи сразу после включения сервера, если в целевое время хост находился в режиме сна:
```ini
[Unit]
Description=Trigger Docker Backup Every Night at 3 AM
Requires=docker-backup.service

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

## 🔍 Диагностика и Мониторинг

* Проверка статуса системного будильника и времени до следующего запуска:
```bash
systemctl list-timers --all
```
* Анализ системных логов выполнения бэкапа:
```bash
sudo journalctl -u docker-backup.service
```
